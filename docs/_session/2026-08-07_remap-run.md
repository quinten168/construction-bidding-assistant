## 1. Decision 2 applied: the FDR treatment generalised to removals

`removal_pavement` had the identical shape to FDR — CSI/Mark's standing rule says pavement removal
"is considered grading work" (a CATEGORY statement), but removal is measured in SY (30 of 41 corpus
rows) or TON (7 rows) while `grading_yards` is CY, and **depth is stated on 0 of 41 rows**, so no
SY→CY conversion is possible.

Applied: `csi_category='grading'` recorded, quantity left where it is counted (for most of these,
nowhere), and the gap made explicitly visible rather than blank. No conversion invented. CSI's own
1.75 Ton/CY factor was deliberately NOT used — it has never been checked against a plan and does not
distinguish bituminous from aggregate base.

### A process finding worth more than the numbers

**`--dry-run` passed clean and the real run died immediately** on `no such column: csi_category`.
The dry-run skips the UPDATE entirely, so it validates the computation and not the SQL. Nothing was
committed (the failure preceded any commit; verified by re-reading the pre-run totals).

This is #65's pattern one layer down: **a clean dry-run is evidence about the numbers, not about the
write.** Now recorded as a comment in `10_remap_buckets.py` next to the fix, so the next person does
not read a green dry-run as proof the run will work.
